# Agent‑Reliability 独立仓库拆分落地方案

> 
> 核心原则：**只做剥离迁移、不重构业务逻辑、保持行为 100% 不变、零反向依赖、API 尽可能兼容**

## 整体实施总览

总共分 8 个阶段，可以按顺序分步执行，每一步都可暂停、可回滚。
整体变更边界

1. 新建独立仓库 `agent‑reliability`
2. 将 Reliability Runtime MVP3 全部逻辑迁移过去
3. 清理全部对 AgentWorld、World、Agent 模型、Scheduler、Memory 的硬依赖
4. 定义一套框架无关的最小通用抽象（`ToolCall`/`Action`/`Decision`/`Audit`）
5. 原 AgentWorld 删除 reliability 源码，通过 `go mod` 引入独立包
6. 两边仓库各自完整跑通单元测试 + 集成回归
7. 补齐独立 Demo、文档、CI、版本标签

执行命令扫描全部导入项

```
# 扫描reliability包所有外部依赖

```

标记三类依赖清单

表格

| 依赖类型 | 处理方案 |
| --- | --- |
| AgentWorld 内部包 `internal/*`、`world/*`、`models`、`scheduler`、`memory` | **必须全部移除**，改用通用接口 / 结构体替换 |

| World 业务硬编码规则 (Pascal 写保护、hotel 密钥) | **规则样例迁移到 examples**，核心 runtime 不能耦合业务 |

> 关键点：**业务策略≠运行时内核**。运行时只提供规则引擎，具体行业规则放到示例目录，内核代码不能依赖任何 World。

记录全部入参、返回结构体、枚举常量 (ALLOW/DENY/ASK/MODIFY)

## 阶段 3：依赖解耦（本次工作难度最高环节）

### 3.2 定义框架无关最小基础模型

在`agentruntime/types.go`，新建通用结构体，**完全不引用 AgentWorld 任何 Model**

```
package agentruntime

import "context"

// ToolCall 通用工具调用结构体，取代原来绑定AgentWorld的Action
type ToolCall struct {
	Name      string
	Arguments map[string]any
	Meta      map[string]string // 附加元数据，调用方可以放入agentId等可选信息
}

// DecisionType 四种决策枚举，必须和原有常量完全一致保证行为不变
type DecisionType string

const (
	ALLOW  DecisionType = "ALLOW"
	DENY   DecisionType = "DENY"
	ASK    DecisionType = "ASK"
	MODIFY DecisionType = "MODIFY"
)

// Decision 返回结果
type Decision struct {
	Type          DecisionType
	Reason        string
	ModifiedCall  *ToolCall // MODIFY时返回修改后的工具调用
	PolicyID      string
	ApprovalToken string // ASK场景下的审批令牌
}

// AuditRecord 审计日志通用结构
type AuditRecord struct {
	ToolCall   ToolCall
	Decision   Decision
	Timestamp  int64
	AgentMeta  map[string]string
}
```

> 
> 所有原来直接 import `agentworld/models`、`agentworld/world` 的地方全部替换成上面通用类型。

### 3.3 依赖分类改造细则

1. **硬引用 Agent 结构体**
内核不再感知什么是 Agent。Agent 相关信息放到 `ToolCall.Meta` 透传进去，运行时只读、不依赖 Agent 实体。
2. **World 专属判断逻辑**
Pascal、Hotel、Economy 的专属规则**移出内核**，放到 `examples/policy_samples` 作为示例策略，内核只提供通用规则执行引擎。
> 
> 内核只负责执行规则，不内置任何业务规则。
3. **数据库依赖**
Audit 模块：内核只产出 AuditRecord，**不绑定任何数据库**。存储实现交给上层调用方 (AgentWorld)；内核只提供回调接口
```
// AuditHandler 审计回调接口，上层实现存储
type AuditHandler func(record AuditRecord) error
```
4. **MCP/HTTP 适配器**
adapter 目录只做 ToolCall 的格式转换，不耦合 AgentWorld MCP 实现。

### 4.4 兼容层（最小改动 AgentWorld）

为了最大程度减少 AgentWorld 改造量，**在 AgentWorld 侧做一层薄薄的适配转换层**，而不是修改 agent‑reliability 内核。

> 
> AgentWorld 侧适配层示例 `agentworld/internal/adapter/reliability_adapter.go`

```
package adapter

import (
	"yourorg/agent‑reliability/agentruntime"
	"yourorg/agentworld/models"
)

// AgentWorld Action → 独立项目通用ToolCall
func ActionToToolCall(action models.ToolAction) agentruntime.ToolCall {
	return agentruntime.ToolCall{
		Name:action.Name,
		Arguments:action.Args,
		Meta:map[string]string{
			"agent_id": action.AgentID,
			"world":action.WorldName,
		},
	}
}

// ToolCall转回AgentWorld内部Action
func ToolCallToAction(call agentruntime.ToolCall) models.ToolAction{
    //类型转换
}
```

**好处：**

- agent‑reliability 完全干净
- AgentWorld 原有业务代码几乎不用大面积改动
- 转换逻辑全部收拢在一个 adapter 文件，方便后续迭代

### 5.2 独立 Demo 示例 examples/demo/main.go

**完全不需要 AgentWorld**即可运行，用于验证项目独立性

```
package main

import (
	"context"
	"fmt"
	"github.com/yourorg/agent-reliability/agentruntime"
	"github.com/yourorg/agent-reliability/policy"
)

func main(){
	//初始化审计回调，简单打印
	auditCallback := func(record agentruntime.AuditRecord) error{
		fmt.Printf("AUDIT: %+v\n",record)
		return nil
	}
	rt := agentruntime.New(agentruntime.Config{},auditCallback)

	//注册一条示例策略：禁止rm -rf /
	rt.AddRule(policy.Rule{
		ID:"block-rm-root",
		Match:policy.ToolNameMatch("shell"),
		Action:policy.DenyAction("禁止删除根目录"),
	})

	//构造工具调用
	call := agentruntime.ToolCall{
		Name:"shell",
		Arguments:map[string]any{
			"command":"rm -rf /",
		},
	}

	dec,err := rt.Check(context.Background(),call)
	if err != nil{
		panic(err)
	}
	fmt.Printf("Decision: %s, Reason: %s\n",dec.Type,dec.Reason)
}
```

运行验证

```
go run ./examples/demo
```

预期输出 `DENY`。

## 风险点 & 规避方案

表格

| 风险 | 解决办法 |
| --- | --- |
| 结构体改动导致 AgentWorld 大量代码需要重写 | 新增薄薄一层 adapter 转换层，隔离两边类型定义，最小改动 |
| 依赖清理不干净，隐性导入 agentworld 包 | CI 增加依赖检查脚本，禁止 import agentworld 路径 |
| 拆分前后行为不一致 | 完整跑一遍全部原有 reliability demo 用例，决策结果快照对比 |
| 循环依赖 agent‑reliability <-> agentworld | 内核侧绝对不 import agentworld，所有上层信息依靠 ToolCall.Meta 透传 |
